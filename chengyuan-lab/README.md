# 澄渊实验室

深海实验室风格的倒水排序微信小游戏。背景是深蓝灰，试管是清玻璃，液体用高饱和色。把叠在一起的色层倒进同色或空管，直到每支试管要么封口、要么是空的。

界面让开，颜色层才是主体。设置里可以打开「色弱辅助」，每一层会叠上固定符号。名字是新起的，不沿用常见的「水排序」标题。200 关数据和规则与这一版一起提交。

## 在微信开发者工具里运行

1. 安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，登录后选择「小游戏」。
2. 导入项目，目录选这个文件夹（里面直接有 `game.js`、`game.json`、`project.config.json`）。
3. AppID 可以先用测试号，或保持 `project.config.json` 里的 `touristappid` 做预览。
4. 编译模式是小游戏、竖屏。点「编译」即可在模拟器里玩。
5. 本机没有开发者工具时，可以用下面的 Node 脚本重画截图、校验关卡。

第一次进入会看到一条说明：进度、音效、震动和色弱辅助只写在本机。点「知道啦」之后才会进首页。

## 换成正式 AppID 和广告位

只改两个地方：

- `project.config.json` 的 `appid`：换成小游戏正式 AppID。现在是占位用的 `touristappid`。
- `js/config.js` 的 `ads`：三个 `adunit-placeholder-...` 换成公众平台流量主里创建的激励视频、插屏、横幅广告位 ID。

相关开关也在 `js/config.js`：

| 字段 | 作用 |
| --- | --- |
| `adsEnabled` | 总开关。`false` 时不创建任何广告。 |
| `grantRewardWhenAdUnavailable` | 开发者工具或广告拉取失败时，是否直接发奖励。上线后如果不能白送，改成 `false`。 |
| `bannerEnabled` | 底部横幅，默认关，避免挡住试管。 |
| `interstitialEvery` / `interstitialMinLevel` | 第 10 关之后，每完成 4 关，在点「下一关」时尝试插屏。 |

激励视频用在：第 21 关起撤销次数用完后的额外 5 次、每关 1 支空试管、额外提示、跳过本关。广告失败且允许兜底时，会提示「广告暂不可用，奖励已发放」。

分享走 `wx.shareAppMessage` / `wx.onShareAppMessage`，标题里带当前关卡。

## 怎么玩

点一支试管，再点另一支。管口连续的同色液体会一起倒出，能装多少倒多少。只能倒进同色，或倒进空管。装满且只有一种颜色的试管会封口。全部试管要么封口、要么是空的，即过关。

选中的试管会以 `#38BDF8` 外发光并略放大。倒不进去的目标会降到 35% 透明度并出现锁。封口时绿色对勾加音效，倒错时红框闪动加音效，不只靠红绿两色。

关卡里可以撤销、重开、加一支空管、看提示。前 20 关撤销不限次数，之后每关 8 次，看视频再加 5 次。步数不超过该关 `goal`（也就是参考解 `par`）得三星，不超过 `goal2` 得两星，过关至少一星。星级、色弱辅助和进度用 `wx.setStorageSync` 存在本机。

前 8 种水色是蓝、青、绿、黄、橙、红、紫、粉。青和黄比标准色暗大约 8%，避免在深色底上发飘。第 9–12 色用同一套深海色系里更分开的深色，主要靠纹理和符号区分（十字、水滴、月牙、六边形）。设置里的「色弱辅助」关掉时只有淡纹理，打开后每一层都有清楚符号。红/绿、蓝/紫靠不同符号分开。

## 难度曲线

200 关由固定种子 `20261112` 生成，所有玩家看到的第 N 关相同。生成方式是从已经分好的局面反向倒液：每一步都是某次合法倾倒的逆操作，所以关卡一定有解。参考解再经 BFS（可证明最短）或束搜索缩短。

`data/levels.js` 里 `exact: true` 表示 `par` 是 BFS 或「步数已经等于色段下界」证明过的最短步数。当前 200 关里有 149 关是这样。其余 `par` 是求解器实际走出的步数，是最短解的上界，三星线就定在这个步数上，因此三星是做得到的。

| 关卡 | 颜色 | 空瓶 | 容量 | 计划打乱 | 参考步数 par |
| --- | --- | --- | --- | --- | --- |
| 1–8 | 2 | 2 | 4 | 3–7 | 3–5 |
| 9–20 | 3 | 2 | 4 | 6–13 | 4–8 |
| 21–34 | 4 | 2 | 4 | 10–20 | 6–11 |
| 35–48 | 5 | 2 | 3 | 10–20 | 7–9 |
| 49–64 | 5 | 2 | 4 | 14–26 | 7–12 |
| 65–80 | 6 | 2 | 4 | 18–32 | 7–15 |
| 81–96 | 7 | 2 | 4 | 20–36 | 9–17 |
| 97–112 | 8 | 2 | 4 | 22–40 | 11–18 |
| 113–126 | 8 | 2 | 5 | 24–42 | 13–24 |
| 127–142 | 9 | 2 | 4 | 26–46 | 13–23 |
| 143–156 | 10 | 2 | 4 | 28–48 | 15–22 |
| 157–170 | 11 | 2 | 4 | 30–52 | 16–25 |
| 171–184 | 11 | 1 | 4 | 26–46 | 15–24 |
| 185–192 | 12 | 2 | 4 | 32–56 | 17–24 |
| 193–200 | 12 | 1 | 4 | 30–54 | 16–24 |

后期是 10–12 色、1–2 个空瓶。容量 3 和 5 的两段用来换瓶子高度，避免全程都是 4 格。

## 重新生成和校验关卡

需要 Node.js 18 以上（本仓库在 Node 22 下跑过）。

```bash
cd chengyuan-lab
npm install          # 只为截图脚本安装 @napi-rs/canvas，小游戏包不会带上它
npm test             # 倒水规则单测 + 200 关可解性、种子稳定性、最短步数核对
npm run generate     # 重写 data/levels.js 和 data/solutions.js
npm run validate     # 和 npm test 里的关卡校验相同，单独跑
npm run screenshots  # 用游戏自己的 Canvas 绘制逻辑导出 1170×2532 截图
```

`npm test` 会：

- 用规则回放全部 200 关的参考解，必须获胜，且每一步都是合法倾倒。
- 按同一种子重新生成，关卡和参考解必须与已提交文件逐字节一致。
- 对标记为最短步数、且步数高于色段下界的关卡，再用独立 BFS 求解，步数必须等于 `par`。

`data/solutions.js` 只给校验和提示研究用，已在 `project.config.json` 的 `packOptions.ignore` 里排除，不会打进小游戏包。截图、测试、脚本、README 同样排除。游戏侧代码、关卡、音效和字体子集大约 270KB，远小于 4MB 主包限制。

音效是脚本合成的短 WAV（`npm run audio`），不是外部音乐。界面字体是文泉驿微米黑的子集，说明在 `fonts/LICENSE-lab-sans.txt`（Apache License 2.0）。

## 目录

```
game.js                 小游戏入口
game.json               竖屏配置
project.config.json     AppID、打包忽略项
js/config.js            广告位 ID 和变现开关
js/main.js              场景、触控、存档、分享
js/core/rules.js        倾倒 / 封口 / 过关，纯函数
js/core/hint.js         两步前瞻提示
js/render/              深海实验室绘制（玻璃试管、水色、界面）
js/ads.js js/audio.js js/storage.js js/fx.js
data/levels.js          200 关固定数据
data/solutions.js       参考解（不进包）
scripts/                生成、BFS/束搜索求解、校验、截图、音效
test/                   规则单测和 200 关校验
screenshots/            1170×2532 实机比例截图
fonts/ audio/
```

渲染全部走 Canvas 2D，没有第三方引擎。布局使用 `wx.getSystemInfoSync` 的屏幕尺寸和 `safeArea`。试管少时一行，多时两到三行，高度会吃满操作区，避免下方空一大块。

## 提审时建议核对的事项

下面是清单，不是法律意见。正式发布前以微信当前文档和审核口径为准。

- 类目：小游戏，休闲益智。简介写清楚是颜色分装 / 倒水排序，不要用其他游戏的名字或素材。
- 隐私：进度、音效、震动和色弱辅助只通过 `wx.setStorageSync` 存在本地，游戏自己不上传账号或通讯录。首次启动有说明。若开通广告，广告组件可能按微信广告策略采集设备标识，隐私保护指引里要用平台要求的方式写上本地存储和广告。
- 广告：流量主开通后再换真实广告位。激励视频必须看完才给奖励；`grantRewardWhenAdUnavailable` 只建议留在开发阶段。插屏不要每关都弹，当前是 10 关之后每 4 关一次。
- 版号与自审：含广告变现的小游戏，上线前要按微信《小游戏运营规范》核对是否需要游戏版号、软著、自审自查报告和适龄提示。规则会变，以提交当周的平台说明为准。
- 包体：主包保持在 4MB 以内。不要把 `node_modules`、截图和 `data/solutions.js` 打进去（项目配置里已忽略）。
- 适龄与内容：无内购支付、无用户生成公开内容、无惊吓内容。音效、震动和色弱辅助可以在设置里切换。
